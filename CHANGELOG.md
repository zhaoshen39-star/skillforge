# Changelog

All notable changes to skillforge are documented here.
Format: [Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versioning: semver.

## [0.4.0] — 2026-11-03

Skills assembled from untrusted text are an injection vector, and quick-start code
blocks are full of noise. This release adds a scanner and a cleaner command extractor.

### Added
- `scan <path>` — static scan of a bundle (or single file) for prompt injection
  (English + Chinese), pipe-to-shell installers, destructive commands, leaked
  credentials (`sk-…`, `ghp_…`, `AKIA…`), invisible Unicode, and HTML comments that
  hide instructions. Exit `1` on high severity; `--lenient` to inspect only; `--json`.
- `build` now scans what it is about to write, records findings in `meta.json.risks`,
  and prints a one-line verdict. `--strict-risk` aborts **before writing** (exit `2`).
- `lint` reports risks and fails a 100-point bundle that contains a high-severity
  finding — structure score alone is not a health guarantee.
- `extract_commands()` — pulls runnable commands out of README shell blocks, strips
  `$`/`>` prompts, comments, install logs ("Collecting…", "Successfully installed…")
  and prose; the generated quick start now leads with these instead of raw blocks.

### Changed
- Quick start section keeps the original blocks as "原文示例" for fidelity, but the
  first fence is the cleaned command list.

### Fixed
- `_looks_like_command()` guards against flag-like log lines being promoted to commands.

## [0.3.0] — 2026-11-03

Generating a skill is useless if the runtime never finds it, or if you have thirty
and don't know which ones are broken. This release adds the install and library layers.

### Added
- `install <skill-dir>` — copies a bundle into the runtime's skills root
  (`$DSH_HOME/skills`, `~/.claude/skills`, or `--dir PATH`), then **reads it back** and
  verifies the three things that silently break discovery: `SKILL.md` present,
  frontmatter `name` equal to the directory name, and every `references/*` mentioned
  in the body actually on disk. Supports `--target auto|dsh|claude`, `--list`,
  `--uninstall`, `--dry-run`, `--force`; refuses bundles scoring under 60 unless forced.
- `lint --all [--roots ROOT ...]` — audits every skill under the detected skills roots
  (or the ones you name) and prints one table; exit `1` if anything is below `--min`
  (default 75), so a whole library can be a CI gate.
- `docs/demo.gif` — a real recorded run (build → 46/100 lint → fix → 94/100) used at the
  top of the README; generated by a script, not hand-drawn.
- README: install and `lint --all` sections, CLI table, updated roadmap and test counts.

### Fixed
- `install` verification no longer counts prose like "见 references/）" as a missing file
  (the filename regex now requires a real `name.ext` token).
- Test suite: 85 checks (install lifecycle, `--list`, dry-run, uninstall, library audit).

## [0.2.0] — 2026-11-03

Generation is only half the problem: skills also go stale and rot silently.
This release closes the loop — generate → audit → fix → detect drift.

### Added
- `fix <skill-dir>` — repairs the mechanical failures the auditor finds:
  non-kebab `name`, missing/too-short `description`, missing trigger words,
  missing `whenToUse`, and `references/*` that the body never links.
  It rewrites only frontmatter and appends a reference list — never body content.
  Refuses to touch directories it did not generate (needs `--force`), because a
  hand-written skill's wording is its value.
- `diff <skill-dir>` — compares the source against the SHA-256 hashes recorded in
  `meta.json` and reports added / removed / changed files. Exit code `1` when stale,
  so CI can fail builds whose skills no longer match their source.
- `--profile dsh|claude|generic` on `build` — target-runtime frontmatter:
  DSH keeps `whenToUse`; Claude-only runtimes fold trigger text into `description`
  (they route on `name` + `description` alone). The scorer now waives the
  `whenToUse` check for `claude`-profile bundles.
- `--dry-run` on `build` — prints what would be generated and what it would score,
  without writing anything.
- `--min N` on `score` — exit `1` when below the threshold, for CI gates.
- `meta.json` now records `profile`, `source_root`, and a per-file hash manifest
  (first 400 files) — the basis for `diff`.

### Changed
- `meta.json` schema bumped alongside `VERSION`; `diff` tolerates old bundles
  that predate the hash manifest (reports them as stale).

### Fixed
- `fix` is idempotent: a second run reports "无需修复" instead of re-appending the
  trigger sentence to `description`.
- Test suite grew from 37 to 64 checks covering profiles, dry-run, diff, fix,
  the fix guard rail, and score thresholds.

## [0.1.0] — 2026-10-31

### Added
- `build` from a local directory, a single file (`.md` / `.pdf` via optional
  `pypdf`), a GitHub-style git URL (`git clone --depth 1`, HTML fallback), or a web page.
- Deterministic generation: `SKILL.md` + budgeted `references/` + `meta.json`,
  with no timestamps in the output.
- `lint` / `score`: 12 weighted checks over 100 points (name, description,
  routing, body size, TODO residue, references, dedupe, placeholders, headings),
  with CI-friendly exit codes.
- `selftest` — offline fixture, no network needed.
- Windows-safe I/O (UTF-8 console, CRLF-normalised reads, mojibake guards).
